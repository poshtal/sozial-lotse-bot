# SozialLotse Bot

Бот-навигатор для людей, которые потеряли или могут потерять работу в Германии.
Он сам задаёт вопросы и показывает, что человек может попросить у ведомств.

Выпускной проект курса AI Engineer. Рабочее название, можно поменять.

> Это информация, а не юридическая консультация. Окончательное решение всегда
> принимает ведомство (Arbeitsagentur или Jobcenter).

## Что уже работает

- Telegram-бот с кнопками: плашка, выбор статуса, вопросы, находка.
- Кнопка «Забудь всё» всегда на виду, переспрашивает перед стиранием и
  убирает из чата саму переписку: и ответы бота, и сообщения человека.
- Тот же разговор в консоли, для проверки логики без Telegram.
- Правило стажа для Arbeitslosengeld: 12 месяцев за последние 30
  (§ 142 и § 143 SGB III). Считает код, а не языковая модель.
- Срок пособия по § 147 SGB III: по месяцам работы за 5 лет и возрасту
  (возраст спрашивается кнопками-диапазонами, точное число не нужно).
  Если человек уже получал пособие за 5 лет, бот срок не считает, а
  объясняет, почему.
- Даты можно писать по-человечески: «7 ноября», «с 1 марта 2026 по сейчас».
  Опечатку в одну букву бот исправляет сам: «1 июля 24 гора».
- Если человек написал только начало работы, бот сам подставляет конец из
  того, что уже знает, и переспрашивает кнопками «Да, верно» или «Нет».
- Память только на время разговора: час тишины или команда `/forget`,
  и ответы стёрты.
- База знаний: закон SGB III режется по параграфам и загружается в Qdrant,
  прежние редакции сохраняются. Поиск проверяется отдельной командой.
- После анкеты бот сам показывает, что человеку может быть доступно и о чём
  обычно не знают: деньги на поиск работы, коучинг, курсы, Gründungszuschuss,
  подработка, Insolvenzgeld и другое. Пункты отбирает код по положению
  человека и праву на пособие (поле `showIf` в `data/questionnaire.json`),
  а подробности по каждому пункту бот рассказывает по закреплённым
  параграфам закона.
- Бот отвечает и на свободные вопросы по тексту закона (RAG): по-русски, со ссылкой на параграф. Если
  в базе нет подходящего текста, отвечает «этого я пока не умею».
- 212 автотестов, включая прогон настоящих обработчиков бота без сети.

## Настройка

1. Создай бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и
   получи токен.
2. Скопируй `.env.example` в `.env` и впиши токен в `TELEGRAM_BOT_TOKEN`.

Файл `.env` в репозиторий не попадает. Без токена бот запускается в консоли.

## Запуск в Docker

Нужен только Docker Desktop.

```bash
docker compose up --build bot
```

В терминале появится строка «Бот @имя запущен». Остановка: `Ctrl+C`.

Консольный режим, без Telegram:

```bash
docker compose run --rm -e INTERFACE=console bot
```

## Запуск без Docker

Нужен Node.js 22 или новее.

```bash
npm install
npm run start:dev
```

Бот сам забирает сообщения у Telegram, поэтому он отвечает, только пока
программа запущена. Сервер и публичный адрес не нужны.

## База знаний

Исходники законов лежат в `data/source`. Это официальные XML-архивы с
[gesetze-im-internet.de](https://www.gesetze-im-internet.de/sgb_3/)
(ссылка «XML» на странице закона).

Загрузка. Запускает только владелец проекта, со своего компьютера:

```bash
docker compose build bot
docker compose run --rm bot node dist/ingest.js --paragraphs 136-164,81-87,38
```

Без `--paragraphs` загружается закон целиком. Повторный запуск с тем же
содержимым ничего не делает. Изменённое содержимое загружается как новая
версия: прежняя остаётся в базе с пометкой `active: false`, поиск её не видит.

Проверка поиска отдельно от LLM:

```bash
docker compose run --rm bot node dist/search.js "сколько нужно проработать для пособия"
```

Команда делает то же, что бот: переписывает вопрос, ищет и печатает
найденные параграфы, оценку сходства и вердикт. С флагом `--raw` вопрос не
переписывается.

## Проверка качества ответов

Контрольный набор лежит в `data/evaluation.csv`: вопросы «как спросил бы
знакомый» и заранее записанное ожидание для каждого.

| Ожидание | Что должен сделать бот |
| --- | --- |
| `answer` | ответить и сослаться на нужные параграфы (колонка `paragraphs`) |
| `refuse` | честно сказать «не умею»: вопрос по теме, но ответа в базе нет |
| `partial` | ответ возможен лишь частично, оценивает человек |
| `out_of_scope` | отсеять сразу, на шаге переписывания |

Запуск (около двух минут, на вопрос уходит два запроса к Gemini):

```bash
mkdir -p reports
docker compose run --rm -T bot node dist/evaluate.js > reports/evaluation.md
```

Флаг `-T` нужен, чтобы в файл попал только отчёт, а ход проверки остался
на экране. Отчёт показывает, совпал ли каждый ответ с ожиданием, на каком
месте в поиске оказался нужный параграф, и оценки сходства нужных и
ненужных кусков, по которым подбирается `MIN_RELEVANCE_SCORE`.

Набор прогоняется после каждого изменения, которое влияет на ответы:
промпт, порог, top-K, модель, состав базы.

Как устроен кусок в базе:

| Поле | Пример |
| --- | --- |
| `source_id` | `sgb-3` |
| `chunk_id` | `sgb-3-p142` |
| `title` | `SGB 3 § 142 Anwartschaftszeit` |
| `location` | `§ 142` |
| `section` | глава и раздел закона |
| `text` | текст параграфа на немецком |
| `version`, `active` | номер загрузки и признак актуальной версии |
| `stand` | редакция закона на момент загрузки |

Один параграф это один кусок. Только параграфы длиннее 3500 знаков делятся
на части, и только по границам абзацев.

## Как бот отвечает на вопросы

1. Модель переписывает вопрос человека языком закона, по-немецки:
   «дадут ли денег, если сам ушёл» превращается в «Sperrzeit Arbeitsaufgabe
   ...». Так поиск попадает в нужный параграф. Вопросы не по теме (погода,
   визы) модель отмечает, и бот сразу отвечает «этого я пока не умею».
2. По этому запросу Qdrant возвращает пять ближайших кусков закона (только
   актуальной версии).
3. Куски с оценкой сходства ниже `MIN_RELEVANCE_SCORE` отбрасываются. Если не
   осталось ни одного, бот отвечает «этого я пока не умею». Это решает код,
   модель при этом не вызывается.
4. Иначе куски и исходный вопрос уходят модели с правилами: отвечать только по
   контексту, по-русски, ничего не обещать, на посторонние просьбы отвечать
   отказом.
5. Модель возвращает JSON: есть ли ответ, текст, номера использованных кусков.
6. Источники под ответом проверяет код: показываются только те куски,
   которые действительно были в контексте.

Если шаг 1 не удался (модель недоступна или ответила не по формату), поиск
идёт по исходному вопросу.

Для тем на кнопках параграфы заданы заранее в `data/questionnaire.json`
(поле `chunks`), поиск по смыслу там не нужен.

Причины сбоев пишутся в лог контейнера строкой `Answer failed (...)`:
только шаг и код ответа, без текста вопроса.

## Как устроен проект

```
data/
  questionnaire.json   дерево вопросов: тексты, кнопки, переходы
  rules.json           числа из закона и ссылки на параграфы
  source/              архивы законов для базы знаний
src/
  questionnaire/       читает и проверяет дерево вопросов
  rules/               проверка условий, чистые функции и тесты
  session/             ответы в памяти, таймер на час, «Забудь всё»
  conversation/        ядро: принимает текст, возвращает сообщения и кнопки
  knowledge/           база знаний: разбор закона, нарезка, векторы, Qdrant
  llm/                 обращение к языковой модели
  answer/              ответ на вопрос по базе знаний: поиск, промпт, источники
  cli/                 общие части служебных команд
  ingest.ts            команда загрузки закона в базу знаний
  search.ts            команда проверки поиска
  telegram/            оболочка для Telegram: кнопки, лимит сообщений
  console/             оболочка для терминала
  clock/               текущее время (в тестах подменяется)
```

Ядро не знает, откуда пришло сообщение. Telegram и консоль это тонкие
оболочки: передают текст в `ConversationService` и показывают ответ.

### Как добавить вопрос или ветку

Правится только `data/questionnaire.json`. Типы узлов:

| Тип | Что делает |
| --- | --- |
| `choice` | вопрос с кнопками |
| `date` | вопрос, ответ на который дата |
| `periods` | вопрос, ответ на который список периодов работы |
| `finding` | бот применяет правило и сообщает результат |
| `message` | сообщение без вопроса |
| `end` | конец разговора, ответы стираются |

При запуске дерево проверяется: ссылка на несуществующий узел останавливает
программу с понятной ошибкой.

## Приватность

- Ответы живут только в оперативной памяти программы.
- Текст сообщений не пишется ни в консоль, ни в файлы.
- Свободные вопросы и найденные куски закона уходят в Gemini API, иначе
  ответить на них нельзя. Ответы на вопросы анкеты (статус, даты) в модель
  не передаются.
- У программы нет HTTP-сервера: наружу не открыт ни один адрес.
- Базу знаний пополняет только владелец, локальной командой. Из чата в неё
  попасть ничего не может. Порт Qdrant наружу не открыт.
- Бот работает только в личных чатах, в группах молчит.
- Фото, файлы и голосовые бот не открывает и не сохраняет.
- «Забудь всё» удаляет переписку из чата Telegram. Для этого бот помнит
  номера сообщений (без текста). Ограничения Telegram: удалить можно только
  сообщения не старше 48 часов, а после перезапуска бота номера теряются.

## Что правила пока не учитывают

Список лежит в `data/rules.json`, в поле `notCoveredYet` у каждого правила.

Стаж: сокращённый стаж 6 месяцев для коротких срочных контрактов
(§ 142 Abs. 2), пересечение с предыдущей Rahmenfrist (§ 143 Abs. 2),
периоды без страховых взносов.

Срок пособия: прежнее пособие за 5 лет (§ 147 Abs. 1 Satz 2 и Abs. 4, бот
спрашивает и в этом случае не считает), короткие контракты (§ 147 Abs. 3),
сокращение срока, например из-за Sperrzeit (§ 148, бот предупреждает словами).
